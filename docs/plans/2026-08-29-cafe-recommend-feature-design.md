# 카페 추천 기능 설계 (2026-08-29)

## 배경

점심 먹고 나서 마실 커피도 골라주는 기능. 사용자는 기존 "혼밥 추천"과 똑같이 랜덤 1곳 추천 방식을 원함 (팀 투표 기능은 카페엔 필요 없음).

## 변경 내용

### 이름/순서 (사용자 확정)

- 탭 순서: **밥집추천** → **카페추천** → **팀투표** (기존 "혼밥 추천"은 "밥집추천"으로 이름 변경, "팀 투표"는 마지막 자리로 이동)
- 밥집추천 화면 제목: "오늘의 추천 메뉴" → "오늘의 추천 식당"
- 카페추천 화면 제목: "오늘의 추천 카페"

### 데이터

`server/cafes.ts`에 `CAFES` 배열 신설. 구조는 `RESTAURANTS`와 동일하되 `isSoloFriendly` 필드는 뺀다 (카페는 혼밥 친화 개념이 안 맞음): `{ id, name, category, rating, price, distance }`.

Claude가 롯데월드타워/롯데월드몰/롯데백화점 반경 1km 내 실제 카페를 웹검색으로 찾아서 5~8곳 정도로 채운다.

### API

`server/app.ts`에 `GET /api/daily-cafe-recommend` 추가 — `CAFES`에서 랜덤 1곳을 반환. 기존 `GET /api/daily-recommend`(식당용)과 동일한 패턴.

### 화면 (`src/App.tsx`)

- `activeTab` 상태를 `'solo' | 'team'` → `'solo' | 'cafe' | 'team'`으로 확장
- 헤더 nav 버튼 순서를 밥집추천 / 카페추천 / 팀투표로 재배치, 라벨 텍스트 변경
- 밥집추천 섹션의 h2 텍스트를 "오늘의<br/>추천 식당"으로 변경
- 카페추천 섹션은 밥집추천 섹션(사진 없앤 1단 레이아웃 버전)과 동일한 구조를 그대로 복제 — badge, "오늘의<br/>추천 카페" 제목, 카페 카드(이름·별점·거리), "다른 카페 추천받기" 버튼. `dailyCafeRecommend` 상태를 새로 만들고 `/api/daily-cafe-recommend`를 호출.
- 팀 투표 섹션은 로직/레이아웃 변경 없음, 탭 순서만 뒤로 이동.

## 범위 밖

- 카페용 팀 투표 (요청 없음)
- 카페 데이터의 실시간 갱신/DB화 (레스토랑과 동일하게, 필요할 때 파일 수정 방식 유지)

## 검증

로컬 dev 서버에서 3개 탭 모두 데스크톱/모바일로 확인 — 특히 새 탭이 모바일 헤더(2줄 레이아웃, flex-1 버튼)에서 3등분으로 잘 들어가는지 확인 필요 (기존엔 버튼 2개 기준으로 만들었던 부분).
